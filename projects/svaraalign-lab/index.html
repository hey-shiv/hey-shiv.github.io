Flagship project / SvaraAlign Lab

Verifier-guided alignment system for raga-faithful AI music generation.

SvaraAlign Lab explores how symbolic music verification, expert preference learning, reward modeling, and reranking can make generative music systems more faithful to raga structure.

  • Alignment
  • Reward modeling
  • Raga verification
  • Generative music

Overview

The project treats raga-faithfulness as an evaluation and alignment problem. A model can generate plausible notes while still violating tonic context, phrase grammar, ascent and descent constraints, or aesthetic expectations that matter to listeners with domain knowledge.

Core question

Can expert feedback and deterministic raga verifiers outperform prompting alone?

MVP target

One raga end to end, 20 clips scored, 50 preferences, reward reranking demo.

Architecture

SvaraAlign separates musical constraints from learned preferences. SvaraJudge provides deterministic raga checks, SvaraTrace stores evidence, SvaraPrefs captures expert A/B labels, and SvaraReward learns the reranking signal.

Pipeline

  • 01 Raga specification Encode tonic, permitted swaras, phrase grammar, ascent/descent, and constraints.
  • 02 Candidate generation Generate or load four candidate clips from one model before expanding scope.
  • 03 SvaraJudge report Load audio, use known tonic, extract f0, map svaras, and save verifier JSON.
  • 04 Expert preference Collect comparisons where musical judgment goes beyond deterministic rules.
  • 05 Reward modeling Learn a quality signal from expert preferences and verifier evidence.
  • 06 Reranking Select outputs that satisfy constraints and score well under learned preference.

Design Decisions

  • Keep symbolic checks explicit so cultural constraints are inspectable.
  • Use expert preference learning only where rule-based verification is insufficient.
  • Represent tonic and phrase context as first-class trace fields.
  • Favor reranking before direct fine-tuning while verifier quality is still improving.
  • Start with one raga, one model, and one metric before broadening the benchmark.
  • Defer DPO until verifier quality, preference pairs, and reward baselines exist.

Failures

  • Tonic mismatch Generated phrases can look valid symbolically while drifting from the tonal center.
  • Rule brittleness Hard constraints catch obvious violations but miss expressive context and intent.
  • Pitch extraction noise All-NaN f0, percussion-heavy clips, or bad sample rates can corrupt verifier evidence.
  • Preference ambiguity Two expert judgments may disagree unless the comparison task is tightly specified.

Lessons Learned

Generative music alignment is not only a modeling problem. It needs careful representation, culturally grounded evaluation, interpretable verifier evidence, and honest handling of the gap between rule validity and musical quality.

Evaluation Philosophy

Evaluation should respect both structure and taste. Symbolic verifiers can protect against clear raga violations, while human preference data should capture phrasing, restraint, and musical judgment that rules alone cannot express.

The first metrics stay intentionally narrow: pitch confidence and forbidden-svara violations. Broader phrase scoring, held-out prompts, reward reranking, and symbolic DPO come only after the verifier produces stable JSON evidence.
