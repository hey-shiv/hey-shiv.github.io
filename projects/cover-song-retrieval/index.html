Project / Cover Song Retrieval

Structure-aware hybrid retrieval for cover song identification.

Given one recording, find every other recording of the same composition—across changes of key, tempo, arrangement, language, and voice—and be honest about how well it actually worked.

  • Music information retrieval
  • Da-TACOS
  • Metric learning
  • Retrieval evaluation

Overview

Cover song identification is a retrieval problem, not a classification problem. The set of works is open, most works have only a handful of versions, and two recordings of the same piece may share no surface audio properties at all. So the system is built as a ranking pipeline: represent each track as a sequence, score every candidate against the query, sort, and measure the ranking.

The project deliberately starts classical. A chroma-plus-alignment baseline in the tradition of Serrà et al. 2008 is implemented and tested first, so that any later neural result has something real to be compared against. The learned half is built on top of it, not instead of it.

Core question

What survives when a song is re-recorded, and can a sequence encoder learn to hold onto it?

Current build

Classical baseline implemented and unit tested: OTI key alignment, subsequence DTW, ranking, MAP/MRR/Recall@K.

Dataset

Da-TACOS (Yesiler et al., ISMIR 2019) ships precomputed MIR features rather than raw audio, which keeps the work on retrieval and learning instead of hundreds of gigabytes of downloads. Its benchmark subset holds 13,000 cover tracks organised into 1,000 cliques, plus 2,000 distractors that belong to no clique and exist purely to punish a system that ranks by loose similarity.

1000 cover cliques 13000 cover tracks 2000 distractors 12 chroma bins 4 retrieval metrics

Every track carries a work ID (WID) and a performance ID (PID). Two tracks are a cover pair when they share a WID. That distinction is the whole evaluation: splits are made at the work level, never the track level, so no composition can appear on both sides of the train/test boundary.

Architecture

Audio to a ranked list, one stage at a time.

  1. Audio Da-TACOS ships precomputed MIR features rather than raw audio, which keeps the work on retrieval instead of hundreds of gigabytes of downloads. Built
  2. Representation Chroma / HPCP: twelve pitch classes per frame. Timbre and octave are discarded on purpose, because they are exactly what a cover changes. Built
  3. Alignment Key invariance through the Optimal Transposition Index over twelve circular shifts, then subsequence DTW over a cosine cost, so tempo drift does not break the match. Built
  4. Embedding A dilated temporal convolution trained with a triplet objective, producing one track-level vector. This replaces the pairwise alignment cost, which is quadratic. Next
  5. Vector search FAISS with exact inner product first. Approximate search is an optimisation, not a result. Next
  6. Retrieval A ranked candidate list scored with MAP, MRR and Recall@{1,10,100} on WID-disjoint splits — written from scratch and tested against rankings worked out by hand. Built

The pipeline separates representation, similarity, and evaluation so that each can be swapped or debugged without disturbing the others. The classical and learned branches share the same evaluation lane, which is what makes them comparable at all.

Pipeline

  • 01 Load and split Parse Da-TACOS metadata into WID-keyed cliques and build work-disjoint splits before anything else runs.
  • 02 Tonal features Reduce each track to a 12-bin chroma sequence, keeping harmony and deliberately throwing away octave and timbre.
  • 03 Key alignment Estimate the Optimal Transposition Index from global mean chroma and rotate the candidate onto the query's key.
  • 04 Alignment score Build a cosine cost matrix and run subsequence DTW so a short query can match anywhere inside a longer candidate.
  • 05 Rank and measure Sort candidates by alignment score, drop the self-match, and score the ranking with MAP, MRR, and Recall@K.
  • 06 Learned embeddings Train a TCN sequence encoder with triplet loss, index with FAISS, and rerank the top candidates with DTW.

Build Status

Stages 01 through 05 are implemented as tested Python modules. Stage 06 is the current work. The split is stated plainly here because a research page that blurs "built" into "planned" is not worth reading.

  • Built — data Da-TACOS metadata loader and two-track clique iterator over the WID/PID structure.
  • Built — transposition Circular chroma rotation and Optimal Transposition Index from global mean chroma vectors.
  • Built — alignment Cosine cost matrix and subsequence DTW returning the accumulated cost and best end position.
  • Built — ranking and metrics Key-aligned candidate ranking, plus average precision, MAP, MRR, and Recall@K written from scratch.
  • Built — tests Unit tests for DTW, transposition, and metrics, validated against examples computed by hand.
  • Next — learned retrieval TCN encoder, triplet-loss training, FAISS index, hybrid reranking, ablations, and bootstrap intervals.

Design Decisions

  • Implement the classical baseline first, so a neural improvement has to prove itself against something real.
  • Write DTW and the retrieval metrics by hand once, before reaching for librosa or a metric-learning library.
  • Split at the work level, never the track level, because two versions of one song are not independent samples.
  • Use chroma rather than a richer spectral feature, since timbre is exactly what a cover version changes.
  • Handle key with an explicit transposition search instead of hoping the model learns invariance from data.
  • Report MAP, MRR, and Recall at three depths, because a single number hides where the ranking actually fails.
  • Start with an exact FAISS index; approximate search is an optimisation, not a result.

Open Problems

  • Global OTI is too coarse One transposition per track pair breaks on covers that modulate, and a per-segment index is not free.
  • DTW does not scale Pairwise alignment against every candidate is quadratic, which is the whole argument for an embedding index.
  • Distractors are the real test Precision on the 2,000 no-clique tracks matters more than recall inside a friendly candidate pool.
  • Length normalisation Raw accumulated cost favours short candidates, so the score has to be normalised before it means similarity.

Lessons Learned

The hardest part of this project has not been the model. It has been the discipline around it: deciding what counts as a correct retrieval, making sure the split cannot leak, and writing the metric carefully enough that a good number is actually good news. Implementing average precision by hand and testing it against a ranking I worked out on paper caught more mistakes than any amount of reading did.

Evaluation Philosophy

The evaluation protocol is part of the contribution. Da-TACOS and the MIREX cover song task both define what a credible comparison looks like, and following them costs less than defending a homemade benchmark later.

The minimum credible claim is staged. First the classical baseline runs end to end on a fixed split and produces numbers. Then the learned encoder is measured on the same split with the same metrics. Only then does a hybrid system mean anything, and any difference between systems has to clear a work-level bootstrap confidence interval before I describe it as an improvement.
