Day 1 - Execution Before Preference Learning

The first AgentAlign milestone is not a model update. It is the infrastructure needed to turn terminal-agent behavior into something measurable: task input, isolated execution, deterministic verification, and structured results.

The goal is to make every agent run inspectable enough that later preference data can point back to concrete evidence instead of vibes.

The initial system flow is:

  1. Task JSON
  2. Schema Validation
  3. Temporary Workspace Creation
  4. File Materialization
  5. Pytest Execution
  6. Structured Verifier Result

What Shipped

The first working path can:

  • load a coding task from structured JSON
  • validate task shape and verifier configuration with Pydantic
  • create an isolated temporary workspace
  • materialize task files and tests inside the workspace
  • run pytest as the deterministic verifier
  • return a structured pass/fail result with logs attached

The verifier detected an intentionally broken implementation:

pytest -q 
FAILED test_task.py::test_expected_output

    def test_expected_output():
>       assert 3.0 == 2
E       assert 3.0 == 2

1 failed in 0.04s

This is the first useful reliability signal: not a subjective model judgment, but a reproducible failure produced by an execution-backed verifier.

The important part was not that the test failed. The important part was that the system created the workspace, ran the verifier, captured the evidence, and returned the failure in a structured way.

System Architecture Built Today

The pipeline is small, but each boundary matters. The task starts as data, becomes a typed object, gets materialized into an isolated workspace, and then gets judged by a verifier whose output can be stored for later preference construction.

1. Schema validation

Tasks enter the system as structured data, then become typed objects before any files are written or tools are run. This keeps malformed tasks from producing noisy execution failures downstream. 

class Task(BaseModel):

The task object currently separates:

  • files to materialize
  • verifier command and expected signals
  • metadata needed for later trace storage

The real task contract is already shaped around problem, environment, and evaluation:

class TaskFile(BaseModel):
    path: str
    content: str

class VerifierConfig(BaseModel):
    type: str
    command: str
    timeout_sec: int

class Task(BaseModel):
    task_id: str
    family: str
    instruction: str
    files: list[TaskFile]
    verifier: VerifierConfig

2. Sandboxed execution

Each run gets an isolated temporary workspace. That gives the verifier a controlled environment and keeps agent-side file changes separate from the real project tree. 

/tmp/random_workspace/

The verifier command is executed programmatically:

subprocess.run(["pytest", "-q"])

Two details matter here: cwd=workspace keeps execution inside the sandbox, and timeout prevents a bad agent run from hanging the evaluator forever.

3. Deterministic verification

The first verifier is intentionally boring. Pytest gives a crisp signal that can be reproduced, stored, and compared across runs. 

pytest pass = success
pytest fail = failure

The verifier result also needs to be data, not console text:

class VerifierResult(BaseModel):
    task_id: str
    passed: bool
    score: float
    stdout: str
    stderr: str
    duration_ms: int

Debugging Notes

  • Wrong Python interpreters can make the verifier fail before the task runs.
  • Broken __init__.py imports can poison otherwise valid modules.
  • Return codes are the first verifier signal: 0 passes, non-zero fails.
  • Structured failures are more useful than clean-looking terminal output.

Reliability Lesson

Useful agent post-training depends on infrastructure around the model:

  • execution that can be replayed
  • verification that produces stable evidence
  • schemas that preserve task and trace meaning
  • evaluations that remain separate from optimization data

Prompting can influence behavior, but the system only becomes improvable when behavior is observable, comparable, and tied to verifier evidence.
